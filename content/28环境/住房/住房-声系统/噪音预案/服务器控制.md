### 方案升级：服务器 + 麦克风 + Home Assistant

这个方案的核心是让你的服务器成为大脑，利用 Home Assistant (HA) 这个强大的开源智能家居平台来整合所有设备，实现高度定制化的自动反击逻辑。

#### 新的连接架构图

```
楼上噪音 → USB麦克风 → 服务器 (运行 Home Assistant) → [噪音分析与判断] → 米家网关 → 智能插座 → 共振音响
```

- **感知 (眼耳):** USB 麦克风，实时监听环境声音。
- **大脑 (决策):** 服务器上的 Home Assistant，分析声音数据，决定是否反击。
- **手臂 (执行):** 米家智能插座，通过网关接收 HA 的指令，控制音响通断。

### 一、硬件准备 (只需增加一个麦克风)

1.  **服务器 (已有):** 确保可以 24/7 运行，并且可以安装 Docker 或其他虚拟化环境（这是运行 HA 最稳定推荐的方式）。
2.  **智能网关 (已有):** 米家多模网关等，确保已接入你的 Home Assistant。
3.  **共振音响 + 智能插座 (方案不变):** 依然是“上电即播”的音响 + 米家智能插座。
4.  **麦克风 (新增):**
    *   **推荐类型:** **免驱 USB 麦克风**。
    *   **为什么:** 即插即用，服务器（通常是 Linux 系统）能轻松识别，无需复杂的驱动安装和 GPIO 接线。价格便宜的即可，我们不是要录音棚音质，只需要它能拾取分贝变化。
    *   **安装位置:** 用 USB 延长线把它吊在或贴在天花板附近，但要远离你自己的音箱、电视、以及服务器风扇等噪音源。

### 二、软件核心：Home Assistant (HA)

如果你的服务器还没装 HA，强烈建议用 Docker 安装，稳定且便于管理。安装后，你需要做几件事：

1.  **接入米家设备:**
    *   通过 HACS (HA 的社区商店) 安装 `Xiaomi Miot Auto` 集成。
    *   配置该集成，登录你的小米账号，HA 就能自动发现并控制你账号下的所有米家设备，包括那个智能插座和震动传感器（震动传感器可以作为辅助或备用）。

2.  **接入麦克风:**
    *   将 USB 麦克风插入服务器。
    *   在 HA 的 `configuration.yaml` 文件中，添加 **Audio** 传感器的配置。它能将麦克风的输入转换成一个实时的分贝值实体 (sensor)。
    *   示例配置:
        ```yaml
        # configuration.yaml
        sensor:
          - platform: audio
            name: "环境噪音水平" # 给它起个名字
            # device_name: "你的麦克风设备名" # 通常可以不写，HA会自动寻找
            # 你可以在HA的硬件信息里找到麦克风设备名
        ```
    *   重启 HA 后，你就会在实体列表里看到一个 `sensor.huan_jing_zao_yin_shui_ping`，它的值会随着音量实时变化。

### 三、反击逻辑：在 Home Assistant 中创建自动化

这是最关键的一步，你的所有智慧都体现在这里。你不再依赖简单的“震动”，而是可以设定更复杂的“噪音模型”。

#### 自动化示例 (在 HA 的“自动化”UI界面或YAML模式下创建)

**目标：** 当夜间检测到**巨大**且**短暂**的冲击噪音（如脚步、跳跃、砸东西）时，自动触发反击。

```yaml
# automations.yaml
alias: 楼上噪音自动反击
description: "夜间检测到高分贝冲击噪音时触发共振音响"
mode: single # 确保自动化一次只运行一个实例，防止连续触发导致混乱

trigger:
  - platform: numeric_state
    entity_id: sensor.huan_jing_zao_yin_shui_ping # 你的麦克风传感器
    above: 75  # 阈值，需要你根据实际情况调试。先设置高一点，避免误触
    for:
      seconds: 1 # 噪音持续1秒以上，过滤掉瞬间的尖锐声

condition:
  - condition: time # 仅在夜间生效
    after: "22:00:00"
    before: "07:00:00"
  - condition: state # 确保反击设备当前是关闭的，避免重复执行
    entity_id: switch.mi_smart_plug_xxx # 你的智能插座实体ID
    state: "off"

action:
  - service: switch.turn_on
    target:
      entity_id: switch.mi_smart_plug_xxx # 打开插座，启动音响
  - delay: "00:03:00" # 反击持续3分钟
  - service: switch.turn_off
    target:
      entity_id: switch.mi_smart_plug_xxx # 关闭插座，停止反击
  - delay: "00:10:00" # 冷却时间，10分钟内不再响应新的触发（通过 mode:single 实现）
```

**逻辑解读:**

1.  **触发 (Trigger):** 当麦克风检测到的分贝值**超过 75**（这个数值需要你对着 HA 界面，观察楼上制造噪音时的峰值来确定）并**持续 1 秒**以上时。这个 `for` 条件非常重要，可以有效过滤掉你打喷嚏、关门等非持续性噪音。
2.  **条件 (Condition):**
    *   必须是**晚上 10 点到早上 7 点**之间。
    *   并且，**智能插座当前必须是关闭状态**。这能防止在一次反击的3分钟内，又被新的噪音重复触发。
3.  **动作 (Action):**
    *   打开插座（开始播放）。
    *   等待 3 分钟。
    *   关闭插座（停止播放）。
    *   由于 `mode` 设置为 `single`，在这次自动化完整运行（包括所有 `delay`）结束前，即使再次满足触发条件，也不会启动新的任务。这天然地提供了“冷却时间”。

### 四、优势与高级玩法

你现在的方案，相比简单的震动传感器，优势是碾压性的：

*   **精确识别:** 麦克风能捕捉到空气传播的声音，对脚步声、拖拽声的识别比震动传感器更灵敏和准确。你可以通过调整分贝阈值和持续时间，精确“建模”楼上的噪音特征。
*   **避免误触:** 你在家正常活动、说话、看电视产生的噪音分贝值通常是平稳的，而楼上的冲击噪音是突发的峰值，很容易通过 `numeric_state` 区分。
*   **数据化运营:** HA 会记录噪音传感器的历史数据。你可以画出噪音曲线图，清晰地看到楼上在哪些时段最吵，甚至可以把图表发给物业或警察作为证据。
*   **无限扩展:**
    *   **手动/自动切换:** 在 HA 界面创建一个开关 (Input Boolean)，让自动化只在这个开关打开时生效，实现一键“布防/撤防”。
    *   **分级反击:** 创建多个自动化。比如，噪音 60-70 分贝，播放2分钟；噪音超过 80 分贝，播放10分钟“加强版”音频（需要更复杂的设备，如可控播放内容的播放器）。
    *   **远程通知:** 自动化触发时，通过 HA 的通知服务给自己手机发一条消息：“已启动‘敦睦邻里’程序”。
